<task type="auto">
  <name>Task 3: Create WordPress upload service</name>
  <files>src/services/wordpress_upload.ts, src/services/index.ts</files>
  <action>
    Create `WordPressUploadService` class following the project's service patterns (see render_article.ts as reference for class structure):

    1. `loadMarkdownArticle(keyword: string)` — reads from `src/repositories/final/phase5_article_{slug}.md` using the same slug pattern as RenderArticleRepository. Throw descriptive error if file not found.

    2. `convertToHtml(markdown: string)` — uses markdown-it to convert Markdown to HTML. Configure markdown-it with html:true (the Phase 5 output contains HTML content blocks like paragraphs).

    3. `uploadToWordPress(request: WordPressUploadRequest)` — orchestrates the full flow:
       a. Load markdown via loadMarkdownArticle(keyword)
       b. Convert to HTML via convertToHtml()
       c. Determine WP endpoint: pageType === "service_page" → `/wp-json/wp/v2/pages`, "blog" → `/wp-json/wp/v2/posts`
       d. Build slug from keyword (lowercase, spaces to hyphens, strip special chars)
       e. Build title from keyword (title case)
       f. POST to WordPress REST API using fetch() with Basic auth (Base64 of username:app_password)
       g. Parse response, return WordPressUploadResponse

    4. Error handling: wrap fetch in try/catch, return meaningful errors for auth failures (401), permission errors (403), and network issues.

    IMPORTANT: Read WP_BASE_URL, WP_USERNAME, WP_APP_PASSWORD from process.env at call time (not constructor), so env changes don't require restart. Validate all 3 exist before making the API call.
  </action>
  <verify>npx tsc --noEmit passes; service file exports WordPressUploadService class with all 3 public methods</verify>
  <done>Service loads markdown, converts to HTML, uploads to WordPress with Basic auth. TypeScript compiles clean.</done>
</task>
